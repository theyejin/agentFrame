## 使用说明（模板，每次复制使用）

每个讨论节点必须固定包含以下 9 个字段，缺一不可：

| # | 字段         | 填写要求                                  |
| - | ---------- | ------------------------------------- |
| 1 | 节点编号       | `N0NN`，递增                               |
| 2 | 日期时间       | 本地时间，精确到分钟                            |
| 3 | 讨论主题       | 一句话说清本次讨论什么                           |
| 4 | 背景与动机      | 为什么现在讨论这件事                            |
| 5 | 讨论内容       | 双方观点、被提方案、争议点；**保留过程而不仅是结论**          |
| 6 | 本次结论       | 已达成的一致；未达成一致时明确写「未达成一致」               |
| 7 | 落实事项（Action） | 可执行动作清单，每项带 `负责人 / 触发时机 / 验收方式`        |
| 8 | 完成进度       | 相对整体目标的百分比 + 已完成条目                    |
| 9 | 剩余进度       | 尚未完成的条目，与完成进度互补，二者合并应覆盖全部范围           |

### 讨论内容

1. **图表类型的选型过程（过程留痕）**：先按需求字面用 archify `workflow`（泳道 + 列网格）产出整体流程图，连续 16 个候选版本（`overall-operations.json` ～ `overall-operations-v14.json`）均无法通过校验。实测得到的硬约束（逐条由报错换得，见 `.archify/` 内各版本文件）：
   1. workflow 的 `fixed-v1` 布局只返回布尔式诊断；`validate --layout-json` 才给出几何数字：**相邻列相连节点必须满足 `列距 > (两节点宽度之和)/2 + 28px`**。
   2. 列距（pitch）不是常数：节点宽 100 时 pitch=80；**节点宽 ≥130 时 pitch 锁死 132**。因此节点宽度必须 ≤52px 才可能不重叠；而中文标签实测 4 字 ≈122px、6 字 ≈218px（HTML 实体 `&#x9009;` 也按字面计宽，不能用来缩宽度）。
   3. 结论：**workflow 类型装不下「每个节点一个中文步骤名」**，且 showcase 档还有 `composition/proper-crossing`、`ambiguous-corridor`、`micro-segment`、`label-canvas-containment` 等构图门；官方示例 `examples/incident-response.workflow.json`、`release-delivery.workflow.json` 在本机 showcase 下同样 `ok=False`，可佐证这不是本项目写法问题。
   4. 最终改用 `architecture` 类型（绝对坐标、`layout.mode` 只能是 `grid`）。第一版（11 组件、5 标签从编排者扇出）触发 `composition/label-route-clearance` 与 `composition/label-gap`（相邻节点横向间隙需 ≥113px）；把布局改为**三列 × 四行 + 足够行距（180px 行距）**后校验通过。
2. **本机浏览器校验阻塞的处置**：`finalize` 的最后一关 `browser-check` 依赖 Chrome 启动，在本机被系统沙箱拦截（报 `Failed to initialize sandbox` / `GPU process isn't usable` / `sandbox initialization failed: Operation not permitted`），`archify visual-check` 同样失败。处置：改用 `archify render`（产出 HTML 不走浏览器门）+ `archify check`（静态校验）验证，**并已用 headless Chrome（`--no-sandbox` + 工作区内 `HOME`/`--user-data-dir`）截图人工核对**。这是环境问题而非图的问题，已记录为待办（见 Action A-09）。
3. **图的内容设计**（`.archify/FLOW-OVERALL-20261012/overall-operations.html`，源候选 `overall-operations-v16.json`）：标题「自媒体创作运营闭环 · 整体运营流程」；12 个组件分三层：① 左列**真人运营人员（三处关口）+ 编排者（唯一）**，② 中列**四条环节 Agent 线**（文案线 / 视觉线 / 视频线 / 分发数据线），③ 右列**外部服务适配层与本地留痕**（生图服务适配器、图生视频适配器、浏览器自动化、本地数据库、飞书文档、热点源）；四条 region 边界即三层职责边界；16 条带标签连接；3 张卡片=三层职责边界 / 三处人工关口（HITL）/ 红线与回写。
4. **与规格的映射自检**：9 条主执行流程（FLOW-1～FLOW-9）逐条能在图上找到落点；三处人工关口与规格 §8.3 的「选择 / 调整 / 授权」三类形态一致；C-01 / C-08 / C-09 三条红线写入卡片。

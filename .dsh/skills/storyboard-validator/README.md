## 1. 职责

输入一份分镜文件 → 按「24 条契约」逐项体检 → 输出问题（必须修）与提示（可接受）两张清单。它只管**结构**，不管画面好不好看。

## 2. 输入

| 字段 | 类型 | 必填 | 说明 | 来源 |
| ---- | ---- | ---- | ---- | ---- |
| `--file` | path | 是 | 分镜 JSON（读 `shots` 数组）或纯文本 | 分镜产物 |
| `--expect` | int | 否 | 期望条数，默认 24 | 调用方 |
| `--target-seconds` | float | 否 | 目标总时长，给了就校验 ±10% | 调用方 |
| `--shot-seconds` | float | 否 | 纯文本输入时每条分镜的时长 | 调用方 |

## 3. 输入校验（进场前，不通过直接退回）

- [ ] 文件存在且可读
- [ ] JSON 必须能解析出 `shots` 数组；文本必须能解析出至少一行分镜
- [ ] `--expect > 0`

退回时返回：`{"ok": false, "reason": "<原因>"}`（退出码 2）。

## 4. 输出

| 字段 | 类型 | 说明 | 落库位置 |
| ---- | ---- | ---- | -------- |
| `shots` | int | 实际条数 | 标准输出 / `--json` |
| `total_seconds` | float | 总时长 | 同上 |
| `problems` | list | 结构问题（必须修） | 同上 |
| `warnings` | list | 提示（如单条描述超过 60 字） | 同上 |
| 退出码 | int | 0 通过 / 1 有结构问题 / 2 读不了 | 调用方判定 |

## 5. 完成判据（自检通过才交给下游）

- [ ] 条数正好等于期望值（默认 24）
- [ ] 编号从 1 连续到 N
- [ ] 每条画面描述非空，前 20 字不与他人重复
- [ ] 给了 `--target-seconds` 时，总时长在 ±10% 内
- [ ] 单条画面描述超过 60 字只记提示，不判失败

## 6. 失败处理

| 失败情形 | 处理 | 上限 | 超限后 |
| -------- | ---- | ---- | ------ |
| 文件不存在/解析失败 | 退出码 2，要求先产出合法文件 | — | 由上游重新生成 |
| 有结构问题 | 退出码 1，逐条列出问题 | — | 上游重新生成或人工修 |

## 7. 依赖

- 共享库：`_shared/text_utils.py`（与生成方共用同一套解析与判定规则）

## 8. 不在本版范围

- 不做画面质量、构图、版权判断（视觉线的 `image-consistency-checker` 与人工关口负责）
- 不做分镜语义连贯性评估（留待复盘环节的复盘报告分析）

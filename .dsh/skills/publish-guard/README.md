## 1. 职责
对一份发布包做发布前自检：成片与封面是否成对存在、平台模板是否存在、标题/标签/封面文案是否合规、有没有人偷偷打开自动提交、关口③ 是否已由真人授权。任何一项不过就阻断并给出人话原因；本工具只检查，不改状态、不写发布记录。

## 2. 输入

| 字段 | 类型 | 必填 | 说明 | 来源 |
| --- | --- | --- | --- | --- |
| `--task-id` | 整数 | 是 | 要检查的任务号 | 编排者派单/真人 |
| `--package` | 文件 | 否 | 发布包 JSON；缺省取该任务最近一份 publish_package 产物 | 命令行/留痕表 |
| `--platform` | 文本 | 否 | 覆盖发布包里的平台（用于换平台复核） | 命令行 |
| `--live` | 开关 | 否 | 按「真的要发布」的标准检查：关口③ 未授权直接阻断 | 命令行 |

## 3. 输入校验（进场前，不通过直接退回）
1. 任务必须存在；没有发布包就退回并提示先跑 browser-publisher prepare。
2. 发布包必须能被 JSON 解析，且含平台、成片、封面、发布准备四类字段。
3. `submit` / `auto_publish` 任一为真立即阻断（C-08）。
4. 标题/标签/封面文案走 `check_publish_prep`（标题 ≤30 字、标签数按平台模板、封面文案 ≤12 字、绝对化用语命中即阻断）。

## 4. 输出
- 标准输出：可读自检报告（✅/❌ + 逐项 ✗/! 说明 + 下一步提示）。
- `--json` 输出：`{ok, blocked, gate3_authorized, problems, warnings}`。
- 退出码：0 = 可进入人工发布（可能有提示项）；1 = 有阻断项；2 = 用法或数据问题。
- **不写任何库表**（不改状态、不写发布记录）。

## 5. 完成判据（自检通过才交给下游）
- 阻断项为空才返回 0；有关口③ 未授权时在 `--live` 下必须阻断。
- 每条阻断项都说清「违反哪条红线 + 怎么修」。
- 检查前后任务的 `tasks.status` 与 `publish_records` 不变。

## 6. 失败处理

| 失败情形 | 处理 | 上限 | 超限后 |
| --- | --- | --- | --- |
| 没有发布包产物 | 退出 2，提示先跑 browser-publisher prepare | — | — |
| 发布包 JSON 坏掉或字段缺失 | 退出 2，指出缺哪个字段 | — | — |
| 发现自动提交意图 | 退出 1 阻断，并把该问题放在 problems 第一条 | 1 次 | 转人工排查调用方 |

## 7. 依赖
`_shared/publish_guard.py`（组装/自检/渲染/发布记录读写）、`_shared/text_utils.py`（发布准备红线）、`_shared/recording.py`、`_shared/db.py`。

## 8. 不在本版范围
不做发布动作、不代替人工授权、不修改发布包（要改就回 browser-publisher 重新 prepare）。
